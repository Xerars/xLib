# xSTM Sample2

> **Project** : xSTM Sample2
> **Author**  : William Hsiao
> **Descript**: xSTM_DWT delay, time, performance and timer event example


## Introduction

This example shows how to add `xSTM_DWT` to an `STM32CubeMX` and `Keil MDK-ARM` project. DWT uses the Cortex-M Cycle Counter for precise delays, time reads, performance measurement and non-blocking timer events.

`App_Init()` runs DWT initialization and the unit test after system setup. `App_Service()` is called continuously from the `while` loop to demonstrate a periodic Timer Event and Timer Macro.


## Usage

#### 1. Create an STM32CubeMX Project

1. Select the target STM32 device and board in STM32CubeMX.
2. Enable the USART used for output and select Asynchronous mode.
3. This sample uses USART2 and `huart2` by default. If another USART is used, update `xSTM_DEBUG_HANDLE` in `xSTM_Config.h`.
4. Configure UART communication parameters and use the same settings in the serial terminal.
5. Select MDK-ARM as the toolchain and generate the project.

#### 2. Confirm the System Clock

Set `xSTM_SYS_CLOCK` in `xSTM_Config.h`. Its value must match the actual System Clock configured by STM32CubeMX, in MHz.

```c
#define xSTM_SYS_CLOCK                   84      //System Clock(MHz)
#define xSTM_DWT_SYS_CLOCK               xSTM_SYS_CLOCK
```

xSTM_DWT uses this value to convert Cycle Counter values to us and ms. An incorrect clock setting produces incorrect delay and time measurement results.

#### 3. Enable MicroLIB

In Keil, open `Project` → `Options for Target` → `Target`, then enable `Use MicroLIB`.

This sample uses `printf` to send DWT test and measurement results to the debug UART.

#### 4. Add Header Paths

In Keil, open `Options for Target` → `C/C++` → `Include Paths` and add the following paths. Adjust relative paths for the actual project location.

```text
../Code
../Code/App
../Code/xSTM
../Code/xSTM/PlugIn
```

Keep the HAL, CMSIS and Core paths generated by STM32CubeMX.

#### 5. Add Source Files

Create or select App and xSTM groups in the Keil Project window. Use `Add Existing Files to Group...` to add:

```text
../Code/App/App.c
../Code/xSTM/PlugIn/xSTM_DWT.c
../Code/xSTM/PlugIn/xSTM_Debug.c
```

`xSTM_DWT.c` provides DWT functions. `xSTM_Debug.c` redirects `printf` to the debug UART. Adding a header path alone does not compile a `.c` file into the Target.

#### 6. Call App from main

Include `App.h` in `main.c`, call `App_Init()` after peripheral initialization, and call `App_Service()` in the while loop.

```c
#include "App.h"

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_USART2_UART_Init();

  App_Init();
  while(1)
  {
    App_Service();
  }
}
```

When using a USART other than USART2, replace `MX_USART2_UART_Init()` with the initialization function generated by STM32CubeMX and update `xSTM_Config.h` accordingly.

#### 7. Build, Program and Open a Terminal

1. In Keil, select `Project` → `Rebuild all target files`.
2. Confirm that the build log includes `App.c`, `xSTM_DWT.c` and `xSTM_Debug.c`.
3. In `Options for Target` → `Debug`, select the active debugger, such as `ST-Link Debugger`.
4. Configure the matching Flash algorithm in `Utilities`, then select `Download`.
5. Open a serial terminal on the debug UART with the same communication settings configured in STM32CubeMX.


## Example Description

#### App_Init

`App_Init()` runs once after startup and demonstrates:

1. `xSTM_DWT_Init()`: enables the DWT Cycle Counter.
2. `xSTM_TEST_DWT()`: runs the built-in delay, time and performance unit test.
3. `xSTM_DWT_DelayCycle()`, `xSTM_DWT_DelayUS()`, `xSTM_DWT_Delay10US()` and `xSTM_DWT_DelayMS()`: blocking delays in different units.
4. `xSTM_DWT_GetCycle()` and `xSTM_DWT_GetUS()`: reads the current Cycle Counter and time in microseconds.
5. `xSTM_DWT_PERF_START()` and `xSTM_DWT_PERF_FINISH()`: measures the execution time of a code section.

#### App_Service

Call `App_Service()` continuously from the while loop. It demonstrates two non-blocking timer methods:

1. `xSTM_DWT_TimerEvent()`: calls `App_DWT_TimerEvent()` every 1000 ms.
2. `xSTM_DWT_TIMER_START()` and `xSTM_DWT_TIMER_FINISH()`: print a message every 2000 ms.

#### Expected Output

At startup, the terminal shows DWT initialization, the built-in unit test, time information and performance measurement. In the main loop, Timer Event increments every second and Timer Macro prints every two seconds.

```text
[xSTM DWT Sample]: Start
[DWT TEST]: Start
[DWT TEST]: Delay : PASS
[DWT TEST]: Time  : ... us
[DWT TEST]: Perf  : ... us
[Time]: ... Cycle, ... us
[Perf Macro]: ... us
[xSTM DWT Sample]: Init Finish
[Timer Event]: 1
[Timer Event]: 2
[Timer Macro]: 2000 ms
[Timer Event]: 3
```


## Notes

#### DWT Support

DWT is provided by the Cortex-M core and actual support depends on the target STM32 device and core. This sample uses STM32F4 and `DWT->CYCCNT`; it is not suitable for targets without a Cycle Counter.

#### Timer Event Count

`xSTM_DWT_TimerEvent()` currently uses one internal static state machine, so it can manage only one Timer Event at a time. Use `xSTM_DWT_TIMER_START/FINISH` macros for multiple independent events, or extend the library with a handle-based timer later.

#### Long Duration Timing

`DWT->CYCCNT` is a 32-bit counter and naturally wraps around. Subtraction correctly handles short elapsed intervals across wraparound, but it is not suitable as a permanently increasing absolute time source.
