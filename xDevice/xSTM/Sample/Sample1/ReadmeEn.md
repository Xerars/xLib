# xSTM Sample1

> **Project** : xSTM Sample1
> **Author**  : William Hsiao
> **Descript**: xSTM_Debug UART input, output and debug feature example


## Introduction

This example shows how to add `xSTM_Debug` to an `STM32CubeMX` and `Keil MDK-ARM` project. It redirects `printf`, `scanf`, `fputc` and `fgetc` through a debug UART.

The sample also demonstrates Info, Warn and Error messages, hexadecimal data output and the built-in unit test. Call `App_Init()` during the initialization stage of `main`, then call `App_Service()` from the `while` loop.


## Usage

#### 1. Create an STM32CubeMX Project

1. Select the target STM32 device and board in STM32CubeMX.
2. Enable the USART used for debug communication and select Asynchronous mode.
3. This sample uses USART2 and `huart2` by default. If another USART is used, update `xSTM_DEBUG_HANDLE` in `xSTM_Config.h`.
4. Configure UART baud rate, data bits, stop bits and parity. Use the same settings in the serial terminal.
5. Select MDK-ARM as the toolchain and generate the project.

#### 2. Enable MicroLIB

In Keil, open `Project` → `Options for Target` → `Target`, then enable `Use MicroLIB`.

This setting allows `printf`, `scanf`, `fputc` and `fgetc` to be redirected by xSTM_Debug through UART.

#### 3. Add Header Paths

In Keil, open `Options for Target` → `C/C++` → `Include Paths` and add the following paths. Adjust relative paths for the actual project location.

```text
../Code
../Code/App
../Code/xSTM
../Code/xSTM/PlugIn
```

Keep the HAL, CMSIS and Core paths generated by STM32CubeMX.

#### 4. Add Source Files

Create or select App and xSTM groups in the Keil Project window. Use `Add Existing Files to Group...` to add:

```text
../Code/App/App.c
../Code/xSTM/PlugIn/xSTM_Debug.c
```

A header path only lets the compiler locate header files. `xSTM_Debug.c` must be added to the Target to provide `xSTM_HexDump`, `xSTM_TEST_Debug_Print` and `xSTM_TEST_Debug_Scanf`.

#### 5. Call App from main

Include `App.h` in `main.c`, call `App_Init()` after peripheral initialization, and call `App_Service()` in the while loop.

```c
#include "App.h"

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_USART2_UART_Init();

  App_Init();
  while(1)
  {
    App_Service();
  }
}
```

When using a USART other than USART2, replace `MX_USART2_UART_Init()` with the initialization function generated by STM32CubeMX and update `xSTM_Config.h` accordingly.

#### 6. Build

In Keil, select `Project` → `Rebuild all target files`. The build log must show both `App.c` and `xSTM_Debug.c` being compiled.

#### 7. Program and Open a Terminal

1. In `Options for Target` → `Debug`, select the active debugger, such as `ST-Link Debugger`.
2. In `Utilities`, enable `Use Target Driver for Flash Programming` and add the matching Flash algorithm.
3. Select `Download` to program the target.
4. Open a serial terminal using the debug UART with the same communication settings configured in STM32CubeMX.


## Example Description

#### App_Init

`App_Init()` runs once after startup and demonstrates:

1. `xSTM_TEST_Debug_Print()`: formatted integer, hexadecimal and floating-point output.
2. `xSTM_TEST_Debug_Scanf()`: character and string input, verifying scanf and fgetc redirection.
3. `printf` and `fputc`: standard output redirected to the debug UART.
4. `xSTM_DEBUG_INFO`, `xSTM_DEBUG_WARN` and `xSTM_DEBUG_ERROR`: categorized debug messages.
5. `xSTM_HexDump` and `xSTM_DEBUG_HEXDUMP`: hexadecimal output for a 16-byte data block.

#### App_Service

Call `App_Service()` continuously in the while loop. This sample prints a service counter every 1000 ms to demonstrate non-blocking periodic messages.

#### Expected Output

At startup, the terminal shows the unit test and requests a character and a string. It then prints standard I/O output, debug messages and HexDump data.

## Notes

#### Unit Test Blocking Behavior

`xSTM_TEST_Debug_Scanf()` waits for terminal input. If interactive testing is not required in production code, set `xSTM_DEBUG_SUPPORT_UNIT_TEST` to `0` in `xSTM_Debug.h`, or do not call the function from `App_Init()`.

#### UART and HAL Configuration

xSTM_Debug uses `huart2` from `xSTM_Config.h` by default. Ensure that the UART is initialized by STM32CubeMX and that `xSTM_DEBUG_HANDLE`, baud rate and terminal settings match.

#### xMeta.h Name Collision

A generic `OR` macro in `xMeta.h` can conflict with register fields in some STM32 HAL headers. Avoid generic macro names such as `OR`, `AND` and `NOT`.
