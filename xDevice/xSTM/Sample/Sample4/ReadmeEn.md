# xSTM Sample4

> **Project** : xSTM Sample4
> **Author**  : William Hsiao
> **Descript**: xSTM_Power clock control and low-power mode example


## Introduction

This example shows how to add `xSTM_Power` to an `STM32CubeMX` and `Keil MDK-ARM` project. It demonstrates HCLK control, clock restoration, and entry into Sleep, Stop and Standby modes.

`App_Init()` controls the clock. `App_Service()` enters the selected mode once after the configured delay.


## Usage

#### 1. Create an STM32CubeMX Project

1. Select the target STM32 device and board in STM32CubeMX.
2. Enable the USART used for output and select Asynchronous mode.
3. This sample uses USART2 and `huart2` by default. When another USART is used, update `USART2_Init()` in `App.c` and `xSTM_DEBUG_HANDLE` in `xSTM_Config.h`.
4. Configure UART parameters and use the same settings in the serial terminal.
5. Select MDK-ARM as the toolchain and generate the project.

#### 2. Enable xSTM_Power

Confirm the following setting in `xSTM_Config.h`:

```c
#define xSTM_SUPPORT_POWER                1       //Support Power
```

When set to `0`, `xSTM.h` does not include `xSTM_Power.h`; calls to `xSTM_Power_*` produce implicit function declaration warnings.

#### 3. Enable MicroLIB

In Keil, open `Project` → `Options for Target` → `Target`, then enable `Use MicroLIB`. This sample sends information to the debug UART with `printf`.

#### 4. Add Header Paths

In Keil, open `Options for Target` → `C/C++` → `Include Paths` and add:

```text
../Code
../Code/App
../Code/xSTM
../Code/xSTM/PlugIn
```

Keep the HAL, CMSIS and Core paths generated by STM32CubeMX.

#### 5. Add Source Files

In the Keil App and xSTM groups, use `Add Existing Files to Group...` to add:

```text
../Code/App/App.c
../Code/xSTM/PlugIn/xSTM_Power.c
../Code/xSTM/PlugIn/xSTM_Sys.c
../Code/xSTM/PlugIn/xSTM_Debug.c
```

`xSTM_Power.c` provides clock and low-power functions. `xSTM_Sys.c` provides `xSTM_SYS_GetTick()`. `xSTM_Debug.c` redirects `printf` to the debug UART. Adding a header path alone does not compile a `.c` file into the Target.

#### 6. Call App from main

Include `App.h` in `main.c`, call `App_Init()` after peripheral initialization, and call `App_Service()` in the while loop.

```c
#include "App.h"

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_USART2_UART_Init();

  App_Init();
  while(1)
  {
    App_Service();
  }
}
```

#### 7. Select a Test Mode

Set `APP_POWER_TEST_MODE` in `App.c`. Start with `APP_POWER_MODE_NONE` to verify clock switching and UART output.

| Setting | Function |
| --- | --- |
| `APP_POWER_MODE_NONE` | Demonstrates clock control only |
| `APP_POWER_MODE_SLEEP` | Enters Sleep mode |
| `APP_POWER_MODE_STOP` | Enters Stop mode |
| `APP_POWER_MODE_STANDBY` | Enters Standby mode |

#### 8. Build and Program

1. In Keil, select `Project` → `Rebuild all target files`.
2. Confirm that the build log includes `App.c`, `xSTM_Power.c`, `xSTM_Sys.c` and `xSTM_Debug.c`.
3. Select the active debugger and matching Flash algorithm, then select `Download`.
4. Open the debug UART in a serial terminal using the STM32CubeMX communication settings.


## Example Description

#### App_Init

`App_Init()` reads the current HCLK, halves it with `xSTM_Power_SetClock()`, and calls `USART2_Init()` to recalculate the UART Baud Rate. It then restores the original clock with `xSTM_Power_RestoreClock()` and initializes UART again.

Changing HCLK changes the APB and UART input clock. Without UART reinitialization, the terminal can display corrupted characters.

#### App_Service

When `xSTM_SYS_GetTick()` reaches `APP_POWER_ENTER_TICK`, the application enters the selected mode once. Sleep prints `Wake from Sleep` after the function returns. Stop and Standby need a wake source. Standby resets the device and does not execute code after `xSTM_Power_Standby()`.

#### Expected Output

With `APP_POWER_MODE_NONE`, output is similar to:

```text
[xSTM Power Sample]: Start
[Clock]: HCLK: 84000000 Hz
[Clock]: Set: 42000000 Hz
[Clock]: Restore: 84000000 Hz
[Power]: Mode: 0 Enter After: 5000 ms
[xSTM Power Sample]: Init Finish
[Power]: Mode Disabled
```


## Notes

#### UART Clock

`USART2_Init()` is bound to USART2 and `huart2`. When another UART is used, update its handle, instance and initialization function together.

#### Low-Power Mode Verification

Prepare a wake source such as an EXTI button, RTC or Wakeup Pin before testing a low-power mode. SysTick can wake Sleep immediately. After Stop wakeup, run `SystemClock_Config()` and reinitialize UART. After Standby wakeup, check `PWR_FLAG_SB` early during startup to identify a Standby wakeup.
