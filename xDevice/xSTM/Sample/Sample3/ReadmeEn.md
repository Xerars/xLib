# xSTM Sample3

> **Project** : xSTM Sample3
> **Author**  : William Hsiao
> **Descript**: xSTM_Sys CPU, device, clock and reset information example


## Introduction

This example shows how to add `xSTM_Sys` to an `STM32CubeMX` and `Keil MDK-ARM` project. It prints CPU, device, system clock, Boot Address and Reset Reason through the debug UART.

`App_Init()` runs the unit test and prints system information after initialization. `App_Service()` is called continuously from the `while` loop, counts down for 60 seconds, and then triggers a Software Reset. The next startup can confirm the Software Reset through Reset Reason.


## Usage

#### 1. Create an STM32CubeMX Project

1. Select the target STM32 device and board in STM32CubeMX.
2. Enable the USART used for debug output and select Asynchronous mode.
3. This sample uses USART2 and `huart2` by default. If another USART is used, update `xSTM_DEBUG_HANDLE` in `xSTM_Config.h`.
4. Configure UART communication parameters and use the same settings in the serial terminal.
5. Select MDK-ARM as the toolchain and generate the project.

#### 2. Enable MicroLIB

In Keil, open `Project` → `Options for Target` → `Target`, then enable `Use MicroLIB`.

This sample uses `printf` to send xSTM_Sys test results and system information to the debug UART.

#### 3. Add Header Paths

In Keil, open `Options for Target` → `C/C++` → `Include Paths` and add the following paths. Adjust relative paths for the actual project location.

```text
../Code
../Code/App
../Code/xSTM
../Code/xSTM/PlugIn
```

Keep the HAL, CMSIS and Core paths generated by STM32CubeMX.

#### 4. Add Source Files

Create or select App and xSTM groups in the Keil Project window. Use `Add Existing Files to Group...` to add:

```text
../Code/App/App.c
../Code/xSTM/PlugIn/xSTM_Sys.c
../Code/xSTM/PlugIn/xSTM_Debug.c
```

`xSTM_Sys.c` provides system information and reset functions. `xSTM_Debug.c` redirects `printf` to the debug UART. Adding a header path alone does not compile a `.c` file into the Target.

#### 5. Call App from main

Include `App.h` in `main.c`, call `App_Init()` after peripheral initialization, and call `App_Service()` in the while loop.

```c
#include "App.h"

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_USART2_UART_Init();

  App_Init();
  while(1)
  {
    App_Service();
  }
}
```

When using a USART other than USART2, replace `MX_USART2_UART_Init()` with the initialization function generated by STM32CubeMX and update `xSTM_Config.h` accordingly.

#### 6. Build, Program and Open a Terminal

1. In Keil, select `Project` → `Rebuild all target files`.
2. Confirm that the build log includes `App.c`, `xSTM_Sys.c` and `xSTM_Debug.c`.
3. In `Options for Target` → `Debug`, select the active debugger, such as `ST-Link Debugger`.
4. Open a serial terminal on the debug UART with the same communication settings configured in STM32CubeMX.


## Example Description

#### App_Init

`App_Init()` runs once after startup and demonstrates:

1. `xSTM_TEST_SYS()`: prints built-in CPU, device, clock, Boot Address and reset information.
2. `xSTM_SYS_GetUID()`: reads the 96-bit UID.
3. `xSTM_SYS_GetCPUID()` and `xSTM_SYS_GetVer()`: reads the Cortex-M CPU ID and revision.
4. `xSTM_SYS_GetDeviceID()` and `xSTM_SYS_GetDevVer()`: reads the STM32 device ID and revision.
5. `xSTM_SYS_GetBootAddress()`: reads the current Vector Table Address.
6. `xSTM_SYS_GetClockInfo()`: reads SYSCLK, HCLK, PCLK1 and PCLK2.
7. `xSTM_SYS_GetReason()`: reads and decodes the current Reset Reason.

#### App_Service

Call `App_Service()` continuously from the while loop. It updates the remaining count every 1000 ms. After counting down from 60 s to 0 s, it calls `xSTM_SYS_SoftReset()` to restart the MCU.

This validates Software Reset and Reset Reason at the next startup. The sample does not call `xSTM_SYS_ClearReason()` so that the Software Reset flag remains available.

#### Expected Output

On the first startup, the output shows CPU, device, clock and the current Reset Reason, then begins the countdown. After Software Reset, the next output should include a Software Reset Reason.

```text
[xSTM SYS Sample]: Start
[SYS TEST]: UID    : ...
[CPU]: UID: ...
[CPU]: ID: 0x... | Ver: ...
[Device]: ID: 0x... | Ver: 0x...
[Device]: Boot: 0x08000000
[Clock]: SYSCLK: ... HCLK: ... PCLK1: ... PCLK2: ...
[Reset]: Reason: 0x...
[Soft Reset]: 60 s
[xSTM SYS Sample]: Init Finish
[Soft Reset]: 59 s
...
[Soft Reset]: 0 s
[Soft Reset]: Reset Now
```


## Notes

#### Performs an Actual Reset

This sample calls `xSTM_SYS_SoftReset()` after 60 seconds, which immediately restarts the MCU. To inspect system information only, temporarily comment out `xSTM_SYS_SoftReset()` in `App_Service()`.

#### Reset Reason Flags

Reset Reason flags remain after reset until `xSTM_SYS_ClearReason()` is called. The sample intentionally preserves the flags so Software Reset can be confirmed at the next startup.

#### UID and Device Information

UID, device ID and revision are hardware-specific. Their values vary between individual chips and STM32 models.
